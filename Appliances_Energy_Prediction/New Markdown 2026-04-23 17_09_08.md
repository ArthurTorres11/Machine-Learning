# Título do projeto

## Previsão de consumo de energia residencial com séries temporais e modelos supervisionados

# Pergunta do projeto

É possível prever o consumo de energia dos eletrodomésticos a partir do histórico recente e das variáveis ambientais da casa?

# Objetivo

Construir e comparar modelos simples de previsão para estimar a variável `Appliances` usando:

- histórico recente do consumo
- variáveis temporais
- temperatura e umidade dos cômodos
- variáveis externas de clima

No dataset, o alvo é `Appliances`, e entre as entradas há data/hora, `lights`, temperaturas e umidades de vários ambientes, além de clima externo e duas variáveis aleatórias (`rv1` e `rv2`).

# Hipótese

Uma hipótese boa e honesta seria:

> Modelos com memória temporal explícita, usando lags do consumo e variáveis de calendário, devem superar baselines simples na previsão do consumo de energia.

Outra hipótese secundária:

> Features temporais como hora do dia e dia da semana devem ajudar bastante, porque consumo de energia costuma seguir rotina.

# Recorte do projeto

Para não complicar demais logo no começo, eu sugiro este recorte:

- prever 1 passo à frente
- como os dados são de 10 em 10 minutos, isso significa prever o consumo no próximo intervalo de 10 minutos
- usar apenas uma série alvo: `Appliances`
- comparar poucos modelos, mas bem

Se quiser simplificar ainda mais, você pode agregar os dados por hora e prever o próximo horário. Isso reduz ruído e deixa a análise mais amigável.

# O que você vai treinar

## Baselines

Você precisa deles para provar que o modelo aprendeu algo.

### Naive forecast

- previsão = último valor observado

### Média móvel

- previsão = média dos últimos `k` períodos

Esses dois já dão uma linha de base muito boa.

## Modelos principais

Eu ficaria em dois:

### Regressão Linear

- ótima para entender comportamento
- fácil de interpretar
- bom primeiro modelo

### Random Forest Regressor

- captura relações não lineares
- lida bem com interações
- costuma funcionar melhor que uma linear em dados tabulares

# Features que você deve usar

## 1. Features temporais

Extraídas da coluna `date`:

- hora
- dia da semana
- fim de semana ou não
- talvez mês

## 2. Lags do alvo

Essas são as mais importantes.

Exemplo:

- `lag_1` = consumo no instante anterior
- `lag_2`
- `lag_3`
- `lag_6`
- `lag_12`

Como a frequência é de 10 minutos, alguns lags fazem bastante sentido:

- `lag_1` = 10 min atrás
- `lag_6` = 1 hora atrás
- `lag_12` = 2 horas atrás
- `lag_144` = 24 horas atrás

Você não precisa usar todos de cara. Pode começar com poucos.

## 3. Estatísticas móveis

- média móvel da última 1 hora
- média móvel da última 6 horas
- desvio padrão móvel

## 4. Variáveis ambientais

O dataset traz várias temperaturas e umidades internas e externas, além de clima externo. Essas podem ajudar, mas eu não começaria usando tudo de uma vez.

# Divisão de treino e teste

Aqui está uma das partes mais importantes:

**não embaralhe os dados.**

Faça divisão temporal, por exemplo:

- 70% treino
- 15% validação
- 15% teste

Ou:

- primeiros meses para treino
- semanas finais para teste

Como o dataset cobre cerca de 4,5 meses, essa divisão temporal faz sentido.

# Métricas

Use pelo menos estas duas:

- `MAE`
- `RMSE`

Por que usar as duas:

- `MAE` é mais fácil de interpretar
- `RMSE` pune mais erros grandes

Se quiser uma terceira:

- `MAPE`, mas só se fizer sentido com os valores e você tratar divisões problemáticas

# O que seria um bom resultado

Para o seu nível, um bom projeto não é “tirar a menor métrica possível”.

Um bom resultado seria:

- montar pipeline temporal corretamente
- não cometer vazamento de dados
- comparar contra baseline
- mostrar que certos lags ajudam
- explicar onde o modelo falha

Se a Random Forest bater o naive e a média móvel com consistência, ótimo. Mas mesmo que o ganho seja pequeno, o projeto continua bom se a análise for forte.
